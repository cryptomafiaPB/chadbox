Design Principles

Architected for Speed & Hardness

Every layer exists for a measurable reason. No bloat, no layers of indirection.

PRINCIPLE // 01

Kernel-Level Isolation

Chadbox interacts directly with Linux kernel primitives (cgroup v2, seccomp filters, and namespaces) without intermediate hypervisor or daemon bloat.

clone(CLONE_NEWPID | CLONE_NEWNET)
PRINCIPLE // 02

Immutable Language Bundles

Runtimes are packaged as immutable SquashFS images. Sandboxes mount them read-only via loop devices, making tampering or runtime pollution impossible.

mount -o ro,loop python3.12.sqfs
PRINCIPLE // 03

Zero External Dependencies

No Postgres, Redis, RabbitMQ, or Celery queues required. The core engine is a single self-sufficient binary with lockless internal ring buffers.

docker run --privileged
PRINCIPLE // 04

Fail-Safe Under Pressure

Adaptive memory backpressure rejects incoming bursts before host resource thrashing occurs. Memory thresholds cleanly trigger SIGKILL without host cascade.

memory.max & cpu.max enforcement

Developer FAQ

Technical Questions Answered

Details on kernel boundaries, memory quotas, network enforcement, and security architecture.

Chadbox enforces multi-layered defense-in-depth: separate mount, PID, network, IPC, and UTS Linux namespaces, coupled with a strict seccomp BPF filter that disallows all dangerous syscalls (including ptrace, bpf, mount, reboot, and raw socket creation). Runtimes are mounted read-only via SquashFS, and writes are restricted to an isolated memory-backed scratch tmpfs with strict size caps.
Chadbox is intentionally engineered as a clean synchronous/streaming execution engine. Instead of buffering tasks into an external broker and causing network round-trip hops, it uses high-efficiency lock-free internal worker rings. This eliminates external points of failure, cuts idle memory to under 45MB, and drops execution dispatch overhead to sub-millisecond levels.
By default, all network namespaces are completely isolated with loopback only (network: false), rendering outbound LAN and WAN traffic physically impossible for the sandbox process. If explicit network access is required, you can enable outbound-only egress routing with DNS filtering.
Chadbox programs cgroup v2 memory.max directly on the child namespace. If an untrusted script allocates beyond the specified quota (e.g., 128MB), the Linux kernel OOM killer terminates the child process with a precise SIGKILL signal in under 1 millisecond, without impacting the host engine or any neighboring executions.
You can assemble any directory containing your interpreter binary and standard libraries, then run mksquashfs ./runtime ./bundle.sqfs -comp zstd. Place the generated SquashFS file into Chadbox's /runtimes mount point; the engine will immediately detect, index, and cache it for execution.
